# UI UX Design and Audit

Use this method in one of two modes selected by the current assignment.

## Pre-design

For a new or substantially changed user-facing journey, turn the accepted scope into a concise brief: navigation, core user flow, information hierarchy, component choices, applicable states, responsive behavior, feedback and recovery. Respect the current stack, design direction and ownership. Include only states that the journey actually needs; common candidates are normal, empty, loading, invalid/error and edge/partial states. Give the brief to Sol and the assigned author; it does not add a product gate or replace the frozen contract.

## Independent audit

Review actual current UI and real user-flow evidence. Check visual hierarchy, spacing and typography, component consistency, focus/keyboard behavior, feedback, recovery, applicable WCAG contrast and relevant usability heuristics. Report concrete issue cards with location, observed behavior, severity, governing principle and actionable repair direction. Do not implement or self-accept the work. Follow the existing final visual and experience review roles and their evidence contracts.

Do not criticize aesthetics in isolation, invent irrelevant state requirements, or treat screenshots as proof of unseen interaction. Pair every finding with a specific user consequence and repair direction.
