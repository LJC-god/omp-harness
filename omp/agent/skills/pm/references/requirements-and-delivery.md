# PM：需求与交付

For one-sentence new complete-product requests, use discovery-and-research.md before treating the brief as a settled PRD; reuse sufficient existing discovery rather than restarting it. Preserve user evidence, Sol decisions, PM inferences and external sources as distinct. Turn accepted innovations into journeys and observable acceptance with value/tradeoffs. Check introduced capabilities for first use, waiting/nonresponse, failure, cancellation and recovery, including retained records and other participants. Keep promises consistent with actual mechanisms and explicit limits; do not mandate extra services or a new review gate.

只从本页选择一个叶子。候选确认前不要读取叶子正文。

| 目标 | 官方叶子 |
|---|---|
| 从发现材料形成工程可用的完整 PRD | `prd-development` |
| 用客户价值先行方式形成新闻稿 | `press-release` |
| 把战略变成有优先级、史诗和顺序的路线图 | `roadmap-planning` |
| 把大目标写成可验证的史诗假设 | `epic-hypothesis` |
| 创建带 Gherkin 验收条件的用户故事 | `user-story` |
| 把用户工作流拆成活动、任务和发布切片 | `user-story-mapping-workshop` |
| 把过大的史诗拆成可交付故事 | `epic-breakdown-advisor` |
| 绘制完整客户旅程、情绪、触点和指标 | `customer-journey-mapping-workshop` |
| 规划关键干系人的参与方式 | `stakeholder-engagement-advisor` |
| 先识别并再排序全部干系人 | `stakeholder-identification` / `stakeholder-mapping` |
