# Controlled-run archive procedure

Read only after a controlled run when preparing, verifying or publishing its archive. Completion remains governed by coding-procedure.md; archive transport is separate.

### Archive close

After a controlled run (success or BLOCK), prepare/verify a local archive when available. Archive handling is separate from delivery and is not required for routine native work. Use these operations in order:

1. `omp_archive` `prepare`
2. `verify`
3. `publish` only when an authorized private archive binding exists and verify passed

Archive `security: PASS`, `localComplete`, or `published` describes archive safety/transport only. The public archive result also reports `taskComplete` and the control completion assessment. Never mark the task or all todo items complete unless `run_complete` succeeds AND any applicable UI/user-approval gates pass. Incomplete and blocked runs are still archived with an explicitly incomplete task outcome.

Eligible: orchestration.sqlite-registered D: Git project roots only. Pass `projectId` and `runId`. Do not pass a free `cwd` as a working root. Same run-owner gate as control: no stable session is `SESSION_REQUIRED`. Before schema, archive root, or Git sentinel work, resident `readonly` / `query_only` preauth MUST verify in order: session, valid project, then stored `project.id` `SAFE_ID` and not quarantine, then run ownership or lifecycle session binding. The same order applies to cwd lookup and lifecycle. Foreign-run mismatch returns only the run ID. Missing git pins are `NOT_MIGRATED`. NEVER put browser profiles, credentials, `.env`, Cookies, Login Data, passwords, local absolute paths, or secrets in the archive. Do not read those files to "include" them.

No binding → local stage under `D:/OMPData/archives/<slug>/<run-id>/` is complete and the outbox stays queued. NEVER `gh repo create`. Publish only when a private `archive_repo` is already bound and security PASS. Remote is canonical HTTPS (`https://github.com/...`) only. Credentials use trusted `gh.exe` `auth git-credential`; if trusted `gh.exe` resolution fails, fail closed (`ARCHIVE_AUTH_UNAVAILABLE`) with no lexical fallback. NEVER put a token in argv, env, or the manifest. Source Git uses trusted `git.exe` only, with isolated config/env: no system/global config, no external hooks (`core.hooksPath=NUL`), no textconv/ext-diff, `GIT_NO_LAZY_FETCH=1`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_ATTR_SOURCE=HEAD`. Child stdout/stderr are streamed against a per-command cap; overflow kills and cancels the child (`GIT_OUTPUT_TOO_LARGE`). NEVER `Response.text`. File sizes use the full 64-bit high/low pair. Git config, attributes, and manifest handle reads each have a purpose-explicit bigint size cap; over cap is `FILE_TOO_LARGE` and MUST NOT allocate. Empty `alternates` / `grafts` sentinels are pinned no-write/no-delete; nonempty poison is `GIT_ALTERNATES` / `GIT_GRAFTS`. Present or missing `config`, `config.worktree`, and `info/attributes` are closed with the same no-write/no-delete sentinel/pin. Include/filter/diff/merge/textconv execution escapes are rejected. Remote payload is the minimal manifest only (`schema`: `omp-remote-archive/v1`; fields exactly `schema`, `projectId`, `runId`, `gitHead`, `status`, `createdAt`, `changedCount`, `untrackedCount`, `baselineSha`). The remote tree is only `runs/<runId>/manifest.json`. `sourceRef` is false: do not push source refs, HEAD, source blobs, or git objects from the project. Dirty patch stays local. Untracked is not copied. Identical manifest publish is idempotent.

`agent_end` / `session_shutdown` MAY stage locally and MUST use the same resident `readonly` / `query_only` preauth (session, run owner, stored `project.id` `SAFE_ID` and not quarantine, then run or session binding) before schema, archive root, Git sentinel, or mutable bootstrap. Lifecycle readonly peek MUST `JOIN runs`, verify a safe `runId`, and require session/project/run project identity plus eligible run status. Corrupt, foreign, or missing bindings are `SESSION_RUN` before `assertGitRoot`. If archive tooling is unavailable or verification fails, record the archive limitation separately. Do not hand-copy, upload, or claim archive success. Successful task verification and run_complete still establish delivery; do not require the user to repair archive internals before reporting the result.
