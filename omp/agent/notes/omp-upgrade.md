## Runtime compatibility gate

`omp-runtime.ts` resolves internal OMP files only from an explicit `OMP_RUNTIME_ROOT` or Bun's global installation. It validates package identity and an explicitly audited `18.2.4`, `18.2.5` or `18.2.6` version before returning an internal path; an unknown version is reported as unverified and no internal module is imported. It never searches a project `node_modules` directory.

Run `bun scripts/check-upgrade.ts` for the candidate mirror. Use `OMP_DEPLOY_ROOT` and `bun scripts/check-upgrade.ts --deployed` to audit a deployed mirror explicitly. The checker verifies reviewed source hashes before importing extensions, so a source change fails closed until it has been reviewed and its inventory updated.

`tests/runtime-compat.test.ts` invokes the distributed candidate checker from a byte-for-byte temporary candidate snapshot. Its approved-source assertion must remain red after source changes until independent review approves replacement literal hashes; do not edit those literals merely to make the test pass. It also appends one byte to a copied extension and imported library and requires the checker to reject each before internal or extension imports. The smoke regression covers missing and invalid markers, unavailable explicit runtime, all six inherited isolation conflicts, source/runtime boundaries, and root or temporary-directory junctions before the launcher creates artifacts. It does not invoke extension factories, a production DB, or any model.

Existing OMP sessions keep the extension modules they already loaded. Start a new session after an approved deployment. For rollback, settle active work and preserve receipts first; restore only reviewed files whose deployed hashes still match the recorded postimage. Do not use rollback to alter databases, sessions, authentication files, or unrelated runtime state.

New diagnostic requests retain the public `{ schema: "omp-check-diagnostic/v1", root }` shape, but the controller stores the private `{ schema: "omp-check-diagnostic/v2", root, identity: { volume, index } }` policy. Its checks and completion require that bound root identity and receipt `identity: { root: { volume, index }, file: { volume, index } }`; missing, malformed, or unknown v2 policy or receipt data rejects. A genuinely restored frozen v1 policy retains its legacy path/hash behavior, and a null policy remains legacy no-policy. Rollback cannot resume an identity-bound v2 contract with old source: preserve its database, receipts, and artifacts, then use recovery or a new run; never rewrite or downgrade the policy.

For isolated upgrade validation, the only inputs are `OMP_EXPERIMENT_ROOT` (a marked D: lab) and `OMP_RUNTIME_ROOT` (the explicit candidate package or its global `node_modules` root). The launcher checks both markers, validates the candidate identity and reviewed version, derives all eight isolation fields, and rejects any inherited nonmatching `OMP_AUTOMATION_LAB_ROOT`, `OMP_RUNTIME_SMOKE_ROOT`, `OMP_AMBIENT_LAB_ROOT`, `BUN_INSTALL`, `TEMP`, or `TMP` before it creates artifacts or imports a runtime module. It never falls back from an invalid explicit runtime.

Use this saved-and-restored PowerShell environment block so terminal defaults or prior isolation settings cannot conflict; it supplies only the two inputs, rather than manually configuring eight values:

```powershell
$lab = 'D:\Labs\omp\final2-20260921\b'
$runtime = (Join-Path $env:USERPROFILE '.bun\install\global\node_modules\@oh-my-pi\pi-coding-agent')
$names = 'OMP_EXPERIMENT_ROOT','OMP_AUTOMATION_LAB_ROOT','OMP_RUNTIME_SMOKE_ROOT','OMP_AMBIENT_LAB_ROOT','OMP_RUNTIME_ROOT','BUN_INSTALL','TEMP','TMP'
$saved = @{}
foreach ($name in $names) { $item = Get-Item "Env:$name" -ErrorAction SilentlyContinue; $saved[$name] = if ($item) { $item.Value } else { $null }; Remove-Item "Env:$name" -ErrorAction SilentlyContinue }
try { $env:OMP_EXPERIMENT_ROOT = $lab; $env:OMP_RUNTIME_ROOT = $runtime; bun scripts/check-runtime-smoke.ts } finally { foreach ($name in $names) { if ($null -eq $saved[$name]) { Remove-Item "Env:$name" -ErrorAction SilentlyContinue } else { Set-Item "Env:$name" $saved[$name] } } }
```

The launcher sets `OMP_EXPERIMENT_ROOT`, `OMP_AUTOMATION_LAB_ROOT`, `OMP_RUNTIME_SMOKE_ROOT`, and `OMP_AMBIENT_LAB_ROOT` to the marked lab; it derives `BUN_INSTALL` from the candidate's `install/global/node_modules` layout and puts `TEMP`/`TMP` below that lab. It runs a separate runtime probe and every suite in its own process, verifies the probe imported the candidate runtime and used the derived temporary directory, and propagates any child failure.
